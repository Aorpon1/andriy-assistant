# Аналізатор лотів Prozorro.Sale

Інструмент збирає **активні лоти** з аукціонного майданчика Prozorro.Sale
(OpenMarket та інші майданчики працюють на цьому ж API), оцінює вигідність
кожного лота і будує зрозумілий звіт: таблицю CSV + інтерактивний HTML
(пошук, сортування, кольорові вердикти 🟢/🟡/⚪/🔴).

## Швидкий старт

```bash
cd parser
pip install -r requirements.txt
python prozorro_lots.py --max-pages 20
```

Після запуску в папці `output/` зʼявляться:
- `report.html` — відкрий у браузері (головний результат);
- `lots.csv` — для Excel / Google Таблиць.

> ⚠️ Запускати треба на машині з **вільним інтернетом**. У хмарному
> середовищі Claude доступ до `public-api.prozorro.sale` заблоковано
> мережевою політикою, тож звіт там не згенерується.

## Як рахується «вигідність»

У Prozorro.Sale поле лота `value` — це майже завжди **стартова ціна
аукціону**, а окремого поля «незалежна ринкова оцінка» в API немає. Тому
«ринкову вартість» інструмент бере з трьох джерел (за надійністю):

1. **Твій файл довідкових цін** (`--reference-file prices.csv`) — найточніше.
   Формат: рядки `keyword,price`. `keyword` шукається у назві/категорії лота.
   Дивись приклад `prices.example.csv`.
2. **Ціна попередніх торгів** для повторних аукціонів зі знижкою
   (поле `discount.previousAuctionValue`).
3. Якщо нічого немає — вердикт `⚪ Треба ціна` (NEEDREF): лот усе одно в
   таблиці, з корисними сигналами (знижка повторних торгів, голландський
   аукціон, кількість ставок), але без рекомендації «купувати».

### Вердикти

| Вердикт | Що означає |
|---------|-----------|
| 🟢 GOOD | старт уже ≤ «макс. ціни» — варто брати участь |
| 🟡 WATCH | дешевше за ринок, але запас маржі ще малий — варто стежити |
| ⚪ NEEDREF | немає з чим порівняти — додай ціну в довідник |
| 🔴 SKIP | старт на рівні/вище ринку — невигідно |

**«Макс. ціна»** = ринкова вартість − запас. Запас задається `--target-discount`
(за замовчуванням `0.30`, тобто готовий платити максимум 70% ринкової ціни).

## Параметри

| Прапорець | За замовч. | Опис |
|-----------|-----------|------|
| `--max-pages N` | 20 | скільки сторінок стрічки пройти (≈100 лотів/стор.) |
| `--since-days N` | 0 | лише лоти, оновлені за N днів |
| `--keyword СЛОВО` | — | фільтр за словом у назві/категорії (напр. `авто`) |
| `--reference-file FILE` | — | CSV довідкових цін `keyword,price` |
| `--target-discount X` | 0.30 | бажаний запас знижки від ринку |
| `--workers N` | 8 | паралельних запитів до API |
| `--debug-one` | — | вивести сиру JSON-структуру одного лота і вийти |

## Приклади

```bash
# Тільки авто за останні 2 тижні, з власними цінами
python prozorro_lots.py --keyword авто --since-days 14 --reference-file prices.example.csv

# Ширше охоплення, агресивніший запас маржі (50%)
python prozorro_lots.py --max-pages 50 --target-discount 0.5

# Якщо поля API зміняться — подивитись реальну структуру лота
python prozorro_lots.py --debug-one
```

## Якщо щось не парситься

API Prozorro.Sale час від часу змінює поля. Запусти `--debug-one`,
подивись реальну структуру і за потреби підправ функцію `parse_auction`
у `prozorro_lots.py` (там усі поля читаються через `.get()`, тож зламатись
важко — найімовірніше треба буде лише уточнити назву поля).
